# Тренировочный Telegram-бот

Общая тренировка в одной закрытой группе, индивидуальные подходы и немедленная
запись в SQLite. Штатный цикл: карточка → подход → `8*50` → следующая подсказка.
Python 3.13–3.14, aiogram 3, SQLAlchemy 2, Alembic. Без внешних сервисов и портов.

## Запуск через Docker

1. Создайте бота через [BotFather](https://t.me/BotFather), получите токен.
2. Узнайте собственный числовой Telegram user id из доверенного клиента/API.
   Username не подходит для OWNER_TELEGRAM_ID.
3. Скопируйте `.env.example` в `.env`, заполните BOT_TOKEN и OWNER_TELEGRAM_ID.
   `.env` не отслеживается git. Не отправляйте его в чат.
4. Запустите:

```bash
docker compose build
docker compose up -d
docker compose logs -f --tail=100 bot
```

Первый запуск выполняет `alembic upgrade head`, затем long polling. Повторные
миграции безопасны. Compose содержит один bot service; SQLite хранится в named
volume `bot_data` по пути `/app/data/gymbot.sqlite3`. Пользователь контейнера
10001:10001; только data и tmpfs `/tmp` доступны для записи. Порты не публикуются.
Не запускайте две копии polling с одним токеном/томом. `down -v` удаляет данные.

5. Добавьте бота администратором в тренировочную группу. Статус администратора
   нужен для получения обычных сообщений `8*50` при включённом Privacy Mode.
   Специально отключать Privacy Mode через BotFather не требуется.
   Не включайте права удаления сообщений, блокировки, изменения группы,
   добавления администраторов и остальные права, которыми бот не пользуется.
   Контракт подтверждён [Telegram Bots FAQ](https://core.telegram.org/bots/faq).
6. Владелец выполняет `/setup_group` в этой группе.
7. Владелец отправляет `examples/program.example.yaml` как документ с подписью
   `/import_program`. После импорта новая версия становится активной.
8. Каждый спортсмен сам выполняет `/bind xrust` либо `/bind tim`.
9. Выполните `/start_train`, выберите день, отметьте участников и нажмите
   «Начать тренировку». Кнопки выбора доступны автору команды и действуют 20 минут.

## Во время тренировки

Пишите `8*50`, `10*32.5`, `10*32,5 тяжело`. Формат всегда **повторы, затем вес**.
Допустимые оценки: `легко`, `норм`, `тяжело`. Произвольный комментарий не принимается.
Повторы: 1–1000; вес: больше 0, до 2000 кг, до трёх десятичных знаков.
История показывает прошлый аналогичный подход, затем последний результат упражнения.
Бот не рекомендует новый вес и не принимает дополнительные подходы сверх плана.

| Команда | Действие |
|---|---|
| `/start_train` | Выбор дня и участников; если сессия уже есть — продолжение |
| `/status` | Программа, день, упражнение, индивидуальный прогресс |
| `/next` | Следующее упражнение; при незавершённых подходах нужна кнопка подтверждения |
| `/choose` | Перейти к любому упражнению дня, сохранив результаты |
| `/skip` | Отметить упражнение пропущенным и перейти дальше |
| `/undo` | Отменить только свой последний подход текущей сессии |
| `/finish_train` | Завершить после подтверждения; результаты сохраняются |
| `/whoami` | Показать свой Telegram id и привязку |
| `/unbind` | Снять собственную привязку, сохранив историю |
| `/bindings` | Список привязок, только владелец |
| `/admin_unbind xrust` | Исправить чужую привязку, только владелец |

На последнем упражнении `/next` предлагает завершение. Возврат через `/choose`
снимает отметку пропуска. Навигация доступна участникам сессии; тренировочные
результаты принимаются только от привязанных участников разрешённой группы.
Старое подтверждение отклоняется, если состояние изменилось. После сбоя доставки
ответа используйте `/status`: результат мог уже сохраниться. Повтор исходного
сообщения не пишет второй подход; для нового подхода отправьте новое сообщение.

## Программа

Формат — в примере YAML. Обязательна schema_version: 1; athlete/day/exercise keys
стабильны, display_name можно менять. reps задаются строками `"8"` или `"6-8"`;
rir — integer 0–10 либо null. Порядок упражнений положительный и уникальный в дне.
У разных спортсменов могут быть разные планы и число подходов. Если плана текущего
упражнения для спортсмена нет, бот показывает это и не принимает его результат.

Лимиты импорта: 128 КиБ, 20 спортсменов, 14 дней, 30 упражнений/день,
20 подходов/спортсмен/упражнение. UTF-8, без YAML anchors/aliases и повторных ключей.
Импорт атомарный; существующий program.key + version не перезаписывается.
Для обновления увеличьте version. Активная тренировка продолжает прежний план.

## Остановка, обновление и резервная копия

```bash
docker compose stop bot
docker compose up -d --build
docker compose restart bot
```

Контейнер завершает polling по SIGTERM; SQLite и состояние находятся в томе.
Для корректной копии **живой** SQLite используйте online backup API (включает
данные WAL), а не `cp` только основного файла:

```bash
mkdir -p backups
docker compose exec -T bot python -c 'import sqlite3; s=sqlite3.connect("/app/data/gymbot.sqlite3"); d=sqlite3.connect("/app/data/backup.sqlite3"); s.backup(d); d.close(); s.close()'
docker compose cp bot:/app/data/backup.sqlite3 ./backups/gymbot.sqlite3
```

В PowerShell используйте `New-Item -ItemType Directory -Force backups` для каталога.
Храните копии отдельно от Docker-хоста; резервная копия содержит персональные данные.
Для восстановления остановите bot, затем выполните (вспомогательный одноразовый
контейнер использует тот же сервис и том):

```bash
docker compose stop bot
docker compose run --rm --no-deps -T -v ./backups:/backup:ro bot python -c 'import sqlite3; s=sqlite3.connect("file:/backup/gymbot.sqlite3?mode=ro", uri=True); d=sqlite3.connect("/app/data/gymbot.sqlite3"); s.backup(d); d.close(); s.close()'
docker compose up -d bot
```

Применяйте восстановление только когда намерены заменить текущее состояние.
Не редактируйте миграции, уже применённые к данным. Обновление кода:
`git pull`, резервная копия, `docker compose up -d --build`, проверка логов и `/status`.

## Локальная разработка

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# PowerShell: .venv/Scripts/Activate.ps1
python -m pip install -r requirements.lock
python -m pip install --no-deps --no-build-isolation -e .
python -m pytest -q
```

Для локального запуска задайте BOT_TOKEN, OWNER_TELEGRAM_ID и DATABASE_PATH
в окружении, затем `alembic upgrade head` и `python -m app`. `.env` автоматически
читает Compose; локальный Python сам `.env` не загружает. В ограниченном Windows
sandbox используйте `pytest --basetemp=data/pytest-local` с отдельным тестовым
каталогом; pytest может очищать этот каталог, не указывайте там рабочую БД.

Архитектура: `handlers/` — транспорт и карточки; `services/` — транзакционные
сценарии; `parsers/` — чистая валидация; `db/` — SQLite-модели. Источник требований
и результаты этапов — в `openspec/`. Реальные токены для тестов не нужны.
