# Решение CP-08

## Исходное состояние

Git status чистый. Первая миграция уже зафиксирована; DecimalText используется
только в Result.weight_kg. Производители/потребители: save_result, история,
сообщение undo и тест БД. YAML содержит только план повторов/RIR, без поля веса.
Текущие лимиты парсера: до 2000 кг и три десятичных знака; они сохраняются.

## Контракт

Result.weight_g — int / SQLite INTEGER, от 1 до 2000000, CHECK также проверяет
SQLite typeof=integer. При записи `int(Decimal_kg * 1000)` точен благодаря
существующему ограничению до трёх десятичных знаков. Для вывода преобразуем
граммы через Decimal / 1000 и форматируем без float. DecimalText удаляется.

Добавить отдельную Alembic revision 0002 после 0001, первоначальную миграцию
не изменять. Миграция проверяет точную представимость старых значений, затем
создаёт weight_g, заполняет целыми числами и убирает weight_kg. Непредставимое
значение отклоняется до изменений схемы. Downgrade возвращает точный TEXT.
Результаты, soft-delete, внешние ключи и индексы сохраняются.

## Проверки

До изменения: узкая suite БД/парсера/тренировки/навигации.
После: миграция пустой и заполненной тестовой БД, повторный upgrade, обратимость,
отклонение дробных граммов, SQLite typeof/сравнения/MAX/AVG, килограммы в
подтверждении/истории/undo и полная suite. Runtime-БД и удалённые окружения не трогаем.
Зависимости и Docker-конфигурация не меняются.

Baseline: `.venv/Scripts/python -m pytest tests/test_database.py
tests/test_result_parser.py tests/test_training.py tests/test_navigation.py -q
--basetemp=data/pytest-cp08-baseline` — 31 PASS, 9.50 с.

Узкая проверка после изменения: те же тесты плюс tests/test_weight_storage.py —
49 PASS, 27.29 с. Upgrade/downgrade/повторный upgrade сохраняют все поля,
soft-delete, индексы и внешние ключи; Alembic check не обнаружил расхождений модели
со схемой. Недопустимые старые веса оставляют схему/version/data неизменными.
Проверка потребителей: в app нет старого weight_kg/DecimalText; прежнее имя
остаётся только в исторической миграции, конвертации и её тестах/документации.

Итог: `.venv/Scripts/python -m pytest -q --basetemp=data/pytest-cp08-full` —
75 PASS, 44.99 с. `python -m compileall -q app migrations tests` и
`git diff --check` — PASS. Diff ограничен хранением веса и связанными
преобразованиями, примерами, тестами и OpenSpec. Рабочая БД не изменялась;
новая миграция применяется штатным Alembic upgrade при запуске приложения.
Docker/Telegram повторно не запускались; упаковка и зависимости не менялись.
