# Экспорт истории тренировок

Доступен только владельцу из `OWNER_TELEGRAM_ID`, в личном диалоге с ботом.
Привязка `/bind` и настройка `/setup_group` для экспорта не нужны.
Сначала откройте профиль бота, перейдите в диалог и нажмите «Начать».
Затем отправьте одну из команд:

| Команда | Документ | Состав |
|---|---|---|
| `/export chatgpt` | Markdown `.md` | Завершённые сессии за последние 42 суток |
| `/export json` | JSON `.json` | Те же сессии в структурированном виде |
| `/export json all` | JSON `.json` | Все сессии, включая legacy, active и aborted |

При вызове в группе бот предложит перейти в личный диалог. История в группу
не отправляется; бот не пытается первым написать владельцу в личные сообщения.
Ошибка доставки не меняет историю — команду можно повторить.

## Период, время и единицы

Обычный экспорт отбирает `status=completed` по времени **завершения** в диапазоне
от момента формирования минус 42 суток до момента формирования включительно.
Времена и группировка дат — UTC, обозначение `Z`; локальный часовой пояс
Telegram-пользователя не определяется. Сессии отсортированы по началу, упражнения
по порядку программы, факты по времени записи с id как вторичным ключом.

JSON имеет `schema_version: 1`. Вес `weight_kg` — **десятичная строка**, полученная
из целого `weight_g`: `32125 → "32.125"`, без промежуточного float. При анализе
используйте decimal либо исходную точность до трёх знаков после запятой.
`units.weight_encoding=decimal_string` явно описывает это представление.

Типы результата:

- `planned` — `planned_set_number` задан; номер сопоставляется с планом.
- `extra` — `planned_set_number=null`, дополнительный рабочий подход.
- `legacy_unplanned` — NULL в программе `legacy_telegram_2026_10_03_05`:
  исторический подход без номера плана, который нельзя считать extra.

Для `exercise_key=farmer_carry` поле `reps` означает **метры**, а `weight_kg` —
вес **одной гантели** (`weight_scope=per_dumbbell`). Для остальных упражнений
`reps` — повторы (`count`), вес — внешняя нагрузка (`external_load`).
Историческое техническое значение **1 кг сохраняется как 1 кг**: исходный
нулевой вес невозможно восстановить по БД. Фактический RIR, комментарии,
аналитика и рекомендации не создаются. `subjective_rating` содержит сохранённое
`easy`, `normal`, `hard` либо `null`. `target_rir` относится только к плану.

`skipped=true` — отметка пропуска упражнения всей группой; уже записанные
факты этого упражнения остаются в экспорте. Результаты с `deleted_at` исключаются.
Все упражнения дня и планы участников присутствуют, даже когда фактов нет.

## Пример JSON

Сокращённый учебный пример одной сессии с одним спортсменом и упражнением:

```json
{
  "schema_version": 1,
  "generated_at": "2026-10-22T12:00:00Z",
  "period": {
    "mode": "last_42_days",
    "from": "2026-09-10T12:00:00Z",
    "to": "2026-10-22T12:00:00Z",
    "selection": "completed_by_finished_at"
  },
  "units": {"time": "UTC", "weight": "kg", "weight_encoding": "decimal_string"},
  "sessions": [{
    "id": 1,
    "started_at": "2026-10-21T10:00:00Z",
    "finished_at": "2026-10-21T11:00:00Z",
    "status": "completed",
    "program": {"key": "strength_2026_10", "version": 1},
    "day": {"key": "tuesday", "name": "Вторник"},
    "athletes": [{"athlete_key": "xrust", "display_name": "xRust"}],
    "exercises": [{
      "exercise_key": "bench_press",
      "name": "Жим штанги лёжа",
      "order": 1,
      "skipped": false,
      "units": {"reps": "count", "weight": "kg", "weight_scope": "external_load"},
      "athletes": [{
        "athlete_key": "xrust",
        "display_name": "xRust",
        "plans": [{"planned_set_number": 1, "reps_min": 8, "reps_max": 8, "target_rir": 3}],
        "results": [
          {"order": 1, "created_at": "2026-10-21T10:05:00Z", "type": "planned", "planned_set_number": 1, "weight_kg": "50", "reps": 8, "subjective_rating": null},
          {"order": 2, "created_at": "2026-10-21T10:08:00Z", "type": "extra", "planned_set_number": null, "weight_kg": "32.125", "reps": 10, "subjective_rating": "hard"}
        ]
      }]
    }]
  }]
}
```

У `json all` период имеет `mode=all`, `from=null`, `to=null`,
`selection=all_sessions`; время снимка остаётся в `generated_at`.
У незавершённой сессии `finished_at` может быть `null`.
Пустая выборка содержит `sessions: []` с остальными полями заголовка.
Служебный `id` сессии — внутренний номер БД, не Telegram ID.

## Пример Markdown

Фрагмент отчёта для той же учебной сессии:

```markdown
## 2026-10-21

### Сессия 1 — completed
Начало: 2026-10-21T10:00:00Z; завершение: 2026-10-21T11:00:00Z.
Программа: strength\_2026\_10, версия 1; день: Вторник (tuesday).

#### xRust (xrust)

##### 1. Жим штанги лёжа (bench\_press)
Пропуск не отмечен.

| Подход | План | Факт (порядок записи) |
|---|---|---|
| Плановый №1 | 8 повт.; RIR 3 | 50 кг × 8 повт. (№1) |
| Дополнительный (extra) | — | 32.125 кг × 10 повт.; тяжело (№2) |
```

## Ручная проверка через Telegram

1. Запустите обновлённый бот штатным способом. Миграции CHG-0004 отсутствуют.
2. Владелец открывает личный диалог, нажимает «Начать», отправляет `/export chatgpt`.
   Приходит документ `.md`, а не история текстом. Откройте файл: даты, спортсмены,
   планы рядом с фактами, extra отдельно. Пустая история также даёт документ.
3. Отправьте `/export json`. Откройте UTF-8 файл: schema_version=1, UTC-период
   42 суток, точные строки весов, только завершённые сессии периода.
4. Отправьте `/export json all`: проверьте legacy, незавершённые сессии с явным
   статусом, `legacy_unplanned`, farmer carry с метрами и весом одной гантели.
5. Сверьте известный отменённый через `/undo` подход: его в файле нет.
6. В группе вызовите `/export json` владельцем: должна прийти только инструкция
   перейти в личный диалог. От другого пользователя команда должна дать отказ,
   как в группе, так и в личном чате.
7. Сравните `/status` и активную программу до/после экспорта: они не меняются.
   Экспорт не создаёт файлов на VPS. Не используйте эту команду как backup SQLite.

Экспорт не содержит Telegram ID, привязок, токенов, действий и журналов сообщений.
Документы формируются только в памяти; файл больше 50 000 000 байт отклоняется
до отправки, без усечения истории. Это консервативный предел облачного
[Telegram sendDocument](https://core.telegram.org/bots/api#senddocument).
При превышении попробуйте экспорт за 42 дня. Разбиение полной истории на части
в эту версию не входит. Достаточная память процесса для снимка всей истории
остаётся эксплуатационным ограничением.
